# Recommended Emoji Set for DevOps Work Items

This document defines a curated set of emojis that render reliably in GitHub-flavored Markdown and Azure DevOps. These emojis provide clarity and consistency across all work item types.

---

## :bookmark_tabs: Story
Use for end-user-focused deliverables.

- :busts_in_silhouette: – User Story  
- :warning: – User Problem  
- :hammer_and_wrench: – Dev Notes  
- :white_check_mark: – Acceptance Criteria  
- :triangular_flag_on_post: – Best Practices  

---

## :hammer_and_pick: Task
Use for developer implementation steps.

- :page_facing_up: – Task Summary  
- :hammer_and_wrench: – Technical Details  
- :white_check_mark: – Acceptance Criteria  

---

## :bug: Bug
Use for defects and fixes.

- :warning: – Problem Statement  
- :mag: – Reproduction Steps  
- :bar_chart: – Expected vs Actual Results  
- :hammer_and_wrench: – Technical Notes  
- :white_check_mark: – Acceptance Criteria  

---

## :sparkles: Feature
Use for grouping stories into significant deliverables.

- :bust_in_silhouette: – Business Value  
- :warning: – Problem Statement  
- :hammer_and_wrench: – Technical Notes  
- :white_check_mark: – Success Criteria  

---

## :milky_way: Epic
Use for long-term initiatives.

- :bust_in_silhouette: – Vision Statement  
- :warning: – Problem/Opportunity  
- :hammer_and_wrench: – Approach/Architecture  
- :white_check_mark: – Success Metrics  

---

# Usage Guidelines
- **Consistency matters**: Always use the designated emoji per section.  
- **One emoji per section header** (avoid doubling up).  
- **Use plain emoji for emphasis** inline (e.g., milestone, bug) but sparingly.
- **Use additional emoji within sections only** if they add clarity or highlight important points.
- **Keep emoji usage consistent and professional**; avoid excessive or unrelated emoji.
- **Emoji should support, not distract from, the content.**
- If Azure DevOps doesn't render the shortcode (e.g., `:busts_in_silhouette:`), paste the **emoji itself**.
