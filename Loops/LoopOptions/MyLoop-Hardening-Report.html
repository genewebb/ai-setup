MyLoop reliability hardening

Borrow the best, preserve what works: the hardening landed

Nine rows (48.R1–R7, R10, R11) turned MyLoop's file-based state into a killable, restartable loop: every write atomic, every shared file locked, every record versioned, every claim fenced by an epoch, every multi-file step journalled, every stranding shape repaired on the next wake, every dead worker found without a human, every state change looked up in one table, and a chaos suite that proves it under kill and race. The scheduler, the dependency rules and the verification discipline were not touched.

1 · What changed, row by row

Each row is one mechanism with one invariant, its own grader (a scripted judge with a self-test that proves it goes RED on the old scripts and on planted traps) and a blind verifier that re-ran everything from a fresh context.

RowMechanismInvariant it establishesGraderClausesMin
48.R1Atomic state writes and quarantine. Every JSON write goes to a temp file, is flushed, then renamed over the target. Bytes that will not parse are moved to rows/_quarantine, never deleted, and named on the report.A state file on disk is always the old valid version or the new valid version. One torn file costs one row, not the loop.hard-1530
48.R2Shared-state mutex. A named system mutex per shared file (Global\myloop-<sha1 of path>) wraps every read-modify-write of dispatched.json, foreman-state.json, wave.json, started.json; waits are recorded as events.Two processes updating one shared file never lose an entry; wave.json is merged, not replaced.hard-2625
48.R3Row version (compare-and-set). Every record carries version; a write compares the version it read with the one on disk under the row lock and is refused as STALE-WRITE when they differ. Update-Row reloads and re-applies only its own change.A writer holding an old copy of a record cannot overwrite newer state; a verdict, a LOST mark or a rejection landing during a long collect survives.hard-3520
48.R4Claim epoch fencing. Each dispatch allocates a monotonically increasing epoch from foreman-state; the attempt, wave.json and the worker's prompt carry it; collect, verdict, reject and LOST quote it and are refused (STALE-EPOCH) when it is not the current attempt's.Only the attempt that holds the claim may advance the row; a late result from an attempt already declared dead lands nowhere.hard-4620
48.R5Dispatch and close journal. journal.jsonl is a write-ahead record: dispatch-intent before the first file, dispatch-committed after the last; the same pair around a close; refusals happen before the intent; a journal that cannot be written stops the step.Every multi-file step has a recorded intent, so a crash between two files is a known shape, not a mystery.hard-5625
48.R6Reconcile -Repair. On every lead wake the report repairs what the journal proves: a dispatch with intent and no commit is rolled back, a missing dispatched entry rebuilt, a half-done close completed, a torn record reconstructed from the journal and the ticket, and dependency cycles named. Read-only by default and byte-identical without -Repair.Stranding shapes F1, F6, F8, F9 heal on the next wake; whatever cannot be proven is listed as RECOVERY-REQUIRES-HUMAN, never guessed.hard-6930
48.R7Automatic LOST. A dispatched attempt records the dispatching process; the wake checks that process, the lead lock owner, the heartbeat and the wave result, and marks the attempt LOST with a reason (lostWhy) instead of printing OVERDUE for a human.A dead worker is found by the loop itself; a LOST attempt always says why.hard-7930

3 · Crash matrix

Each label is a point where the process is killed mid-step. After the kill, a wake runs Reconcile -Repair; the case passes only if the loop's invariants hold (no torn file, no duplicate entry, no row stranded, no lost result) and a second repair pass finds nothing to do. Baseline is the byte-identical pre-hardening copy of the scripts.

6 · How it was verified

  • Staging, never in place. Every row was built in a cumulative staging copy of the scripts and landed by atomic copy only after its grader went GREEN against the staging folder and RED against the previous one. The pre-hardening copy is kept as the permanent baseline.
  • Grader plus self-test. Nine graders, 61 clauses. Each self-test proves the grader RED on the old scripts, GREEN on a model repair, and RED on the exact clause for three to five planted traps (a version that is bumped but never compared, a comparison outside the lock, a refusal that is only a warning, a re-dispatch that drops the version, and so on).
  • Blind verification per row. A fresh-context verifier re-ran the grader, the self-test, the suite and the diff for every row. All nine came back PASS_WITH_NOTES; every finding was either fixed in the next landing and re-confirmed by a run, or carried by name in section 7.
  • Cross-row regression sweep. Before the last landing every earlier grader was replayed over the final staging. The transition table (R10) made two earlier probes illegal (a verdict on a dispatched row, a second LOST mark); the table was kept as authoritative and the probes reshaped to legal lifecycles.
  • Findings that changed the code (all landed and re-verified): pause and lead-release writes under the lock; the regression selector no longer replays a grader because a three-letter file name appears in its prose; a build or test step fails only on a thrown error or a non-zero exit; a non-lead repair reports instead of throwing; a reconstructed record takes its seat from the ticket; a LOST mark always records why; a collect keeps a LOST or REJECTED status on the attempt and decides per write attempt whether its final write is a transition.

7 · Remaining risks

MEDIUM48.R8 (wave-aware collect) and 48.R9 (accept-ticket and auto-dispatch) are parked. The wave-null LOST path and the transition table's Collect-Wave.ps1 owner entry exist but nothing drives them yet; finished workers still wait for the lead's hand collect. MEDIUMTwo skill test suites running at once produce load-induced false failures in the hard-3 collect-window probe (seen once by the R10 verifier, clean solo). The graders and the suite must run one at a time; nothing enforces that. MEDIUMThe graders' detached process launches do not quote the vault path with spaces; every live run goes through the space-free alias, and a run pointed at the vault path fails as "the collect never reached the build step". LOWSet-RowField can write any field by name and is dot-sourced everywhere; a future caller could bypass the transition guard invisibly to the grader's static clause. Declared reflection residual. LOWThe version compare is skipped when the record file is absent or unparseable, so a quarantined record can be written back from a stale object with no event. LOWCycle detection runs inside Reconcile; Get-ReadySet still reports edges only. LOWAdd-LoopEvent runs inside the critical section and can hold a lock about 2 s on a contended events file. LOWThe board tool locks started.json under the dispatched.json lock name; correct today, breaks the one-lock-per-file rule. LOWThe R5 test case names a close half it never asserts; Close-Row.ps1 logic is duplicated between the skill and the in-repo tool; a never-cleared allocatedEpoch variable in the hard-4 grader is unreachable. LOWRace children from the chaos suite's pre-fix runs earlier in the day are still alive in temp (they waited on a barrier that was never released); post-fix runs leave none. They hold no live lock.

8 · Architecture judgment

The KEEP MYLOOP verdict holds and is now stronger. File-based state with atomic writes, a per-file mutex, a record version, a claim epoch and a write-ahead journal gives this loop the durability the two candidates promised, at its scale (about a hundred records, at most seven workers) without a database, a daemon or a second scheduler. The mechanisms compose: the table decides what may change, the version decides whose copy is current, the epoch decides whose claim is live, the journal decides what a crash left behind, and the repair engine acts only on what the journal proves.

What the hardening did not do, by design, is change throughput. Seat loss was measured as mostly supply-bound (no ticket ready) and lead-bound (a finished worker waiting for a hand collect); R8 and R9 address the second and remain parked, and the autoresearch programme that would optimise the first was scheduled to build only after this hardening.

The loop is paused after this report. Nothing is dispatched until released.
