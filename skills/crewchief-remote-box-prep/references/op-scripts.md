## The op-script layer — `RemoteWindowsOps`

`Executors/RemoteWindowsOps.cs` is a **pure, network-free, unit-tested** static helper (0 in-process side effects) that the ServiceControl / AppPool / IisReset executors and the two inventory pickers use to run their operation on a remote host over `DefaultRemoteCommandRunner`. It is the service-family analogue of the installer family's `msiexec` command build.

Verified conventions (all unit-tested in `RemoteWindowsOpsTests.cs`):
- **`PowerShellArgs(script)`** — packs the inner op-script as `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <base64 UTF-16LE>`, so multi-line scripts carry with no quoting hazards.
- **Inner-script JSON contract** — the happy path emits ONE compact JSON object `{ ok, previous, final, timedOut }`; failure emits `{ ok:false, error }` and `exit 1`. Builders: `BuildServiceControlScript` (`Get-Service` + Start/Stop/Restart), `BuildAppPoolControlScript` (`WebAdministration`), `BuildServiceListScript`, `BuildAppPoolListScript`, plus the inventory pair `BuildInstalledProductsScript` (Uninstall registry keys → `{ProductCode, DisplayName, InstallLocation}` JSON, parsed by `ParseInstalledProducts`) and `BuildResolveConfigurationExeScript(installLocationHint)` (locates `Configuration.exe` on the target, robust when the registry `InstallLocation` is blank).
- **`BuildFileBrowseScript(path, filePattern, driveMap = null)`** — the design-time remote file "Browse…" script, run by `IRemoteFileBrowser`/`DefaultRemoteFileBrowser` (`Executors/IRemoteFileBrowser.cs`) over the credentialed WSMan transport for the editor's Install-MSI / Configure exe/license dialogs. Emits one JSON object `{ currentPath, parentPath, directories[], files[], error }`; a blank path returns the roots view (`DriveInfo` drives, `Get-SmbMapping`, `HKEY_USERS\<sid>\Network` persistent mappings, Explorer nethood `.lnk` targets). Drive Map integration (2026-07-22):
  - `driveMap` is the operator-curated **Drive Map** reference set (letter → UNC); `IRemoteFileBrowser.ListAsync` gained the matching parameter and `FileBrowserDialog` supplies the set (read once per dialog open via `ReferenceStore.Get(ReferenceDataSets.DriveMap)`). Only well-formed NON-identity entries embed as a PS hashtable (key must be a 2-char `X:`; blank values, the shipped `"D:" → "D:"` identity placeholders, and non-letter keys are skipped). The roots view appends the map's UNC values (`\\*` only); a typed path whose drive fails `Test-Path` is translated letter → UNC when the map has the letter AND the candidate passes `Test-Path`.
  - A still-unresolved path throws a FRIENDLY error ("Path not found from this remote session: … type the UNC path (\\server\share\…) instead, or set the letter in the CrewChief Drive Map reference data…") with a self-diagnosing hint: "No Drive Map entry found for X:" vs "Drive Map translated it to \<UNC\>, but that was not accessible from this session: \<underlying exception\>" — the probe's exception (access denied / bad credentials / name not resolved) IS the diagnosis. The `Test-Path` guard exists because without it `Get-ChildItem -LiteralPath $p -Directory` on a nonexistent drive fails with PowerShell's baffling "A parameter cannot be found that matches parameter name 'Directory'" (`-Directory` is a FileSystem-provider DYNAMIC parameter that never binds when the drive is unknown). Tests: `RemoteWindowsOpsTests.BuildFileBrowseScript_*`. <!-- example-path -->
  - WHY the session scans can't see a mapped letter: drive letters are per-interactive-logon; `Get-SmbMapping` is logon-session-scoped; `HKU\<sid>\Network` shows only LOADED hives and only PERSISTENT mappings — an Azure File share mapped by a logon script / `net use /persistent:no` is undiscoverable from the WinRM network logon. Operator action: set the letter's real UNC in **Reference Data → Drive Map**. Open caveat: reaching an Azure Files UNC from the WinRM session may still need auth (a storage-key `net use` in-session, or AD-integrated auth + CredSSP for the second hop). UI side: [[crewchief-web-ui]] "Remote Browse…".
- **`EscapePs`** doubles single quotes for safe interpolation into the script.
- **Timeouts** — `EffectiveTimeout(t) = t > 0 ? t : 600` (600 s default); `TransportTimeoutSeconds(t) = EffectiveTimeout(t) + 60` so the WSMan transport outlives the in-script wait by a 60 s margin.
- **Parsers** — `ParseServiceControlResult` / `ParseAppPoolControlResult` map the compact JSON back onto the existing `ServiceControlRunResult` / `AppPoolRunResult` types; `ParseServiceList` / `ParseNameList` tolerate `ConvertTo-Json`'s bare-single-element quirk (a lone object is not wrapped in an array).
