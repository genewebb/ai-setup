## The box-prep steps

`GetValidationError()` (returning null when valid) is the intended single validation entry point on each step. **Orchestrator delegation is partial** (`Orchestration/UtilityOrchestrator.cs`): it delegates to `GetValidationError()` for **Uninstall (~605), Install (~615), Configure (~625)**; **ServiceControl (~545) and AppPool (~589) are validated inline** via `TryParseAction`; **IisResetStep** has a `GetValidationError()` but has **no case** in that orchestrator switch. When authoring, still treat each step's `GetValidationError()` as the truth for whether it's well-formed.

All six steps also carry the shared remote fields: `credentialUserId`/`credentialPassword` (preferred Run As pair), `credentialSecretName` (legacy fallback), and `remoteAuthentication` (Default/Negotiate/CredSSP).

- **`InstallStep`** (`msiPath` required; optional `arguments`, `targetComputer`, Run As fields). `InstallExecutor`: local resolves the exact MSI via `IProductInstallRunner` then installs; remote builds `msiexec /i <msiPath> /qn /norestart` + the argument list, stages the MSI via `StageFiles`, and runs it over WSMan. **Arguments are split BEFORE token resolution** (`DefaultProductInstallRunner.SplitArguments(step.Arguments)` then `ApplyTokens` per element, `InstallExecutor.cs:~139-141`) so a token resolving to a spaced value (e.g. `INSTALLDIR={{$ref:...}}` → `%ProgramFiles%\App`) stays ONE msiexec argument. `IProductInstallRunner.InstallAsync` now takes `IReadOnlyList<string> arguments` (the runner no longer splits — `IProductInstallRunner.cs:68-70,117-119`). `InputText` keeps the arguments UNRESOLVED so a `{{$config:...}}` secret is never persisted in clear.
- **`UninstallStep`** (at least one of `productNames`/`productCodes`; optional `targetComputer`, Run As fields, `dryRun`). Enumerates installed products so a missing product is skipped (idempotent) — **including remotely**: on a remote target with `productNames`, `UninstallExecutor` first enumerates the TARGET's installed products over WSMan (`RemoteWindowsOps.BuildInstalledProductsScript` + `ParseInstalledProducts`, `UninstallExecutor.cs:~277-311`) to resolve names → product codes, then runs `msiexec /x <code>` per product over WSMan. Explicit `productCodes` skip the enumeration.
- **`ConfigureStep`** (`configurationExePath` required; `switches` dict + raw `arguments` escape hatch; optional `targetComputer`, Run As fields, `workingDirectory`). **Validation requires a non-blank `licenseFile` switch** (`GetValidationError`, `ConfigureStep.cs:~164-168`) — a Profisee configuration run always needs a license file. `ComposeArgumentString(Func<string,string>? resolveValue = null)` emits each enabled switch (ordered) as `/name:value` then appends `arguments` — **each switch value (and the raw `arguments`) is token-RESOLVED BEFORE the whitespace-quote decision** via `resolveValue`, because a `{{token}}` has no whitespace and quote-then-resolve shredded `Default Web Site` into 3 arguments (site "Default" → Configuration.exe IIS site lookup NRE'd). The executor composes TWICE (`ConfigureExecutor.cs:~136-137`): the no-resolver call for `InputText` (so `{{$config:...}}` secrets aren't persisted in clear), the resolver call for execution. Defaults the working directory (local + remote) to the exe's own folder (see [Working directory](#working-directory-on-the-target)). Local via `IProcessRunner`, remote via WSMan. (`switches` catalog is its own topic.)
- **`IisResetStep`** (`action` = `Recycle`/`Restart`(legacy synonym)/`Stop`/`Start`; optional `targetComputer`, Run As fields, `dryRun`). Local/legacy runs `iisreset [computername] /restart|/stop|/start` via `IProcessRunner`; `Recycle`→`/restart`. With a resolved credential on a remote target, runs `iisreset /flag` **ON** the target over WSMan (no computer-name arg). Requires elevation for the local path. A full IIS bounce (W3SVC+WAS), distinct from `AppPoolStep`.
- **`ServiceControlStep`** (`serviceName` + `action` Start/Stop/Restart; optional `targetComputer`, Run As fields). **Dual-mode**: local → `ServiceController(name)`; remote + credential → `RemoteWindowsOps.BuildServiceControlScript` over WSMan (works under LocalSystem); remote + no credential → legacy `ServiceController(name, machine)` RPC as process identity (⚠ typically fails under the LocalSystem service; logs a warning).
- **`AppPoolStep`** (`appPoolNames[]` + `action` Start/Stop/Recycle; optional `staggerSeconds`, `targetComputer`, Run As fields). **Dual-mode**: local → `ServerManager`; remote + credential → `RemoteWindowsOps.BuildAppPoolControlScript` over WSMan (the credential is resolved ONCE for the whole app-pool loop); remote + no credential → legacy `ServerManager.OpenRemote(machine)` as process identity (⚠ warning).
