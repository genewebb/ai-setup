# CrewChief Matching pack

Repo: speed-merchants, `CrewChief/packs/matching` (Gene commits). Built 11/05/2026 on the Connect pack pattern
(`crewchief-workload-packs`). Results log: `Q:\Work\Work\99 Documentation\Connect\Matching Rewrite Results.md`.

## Layout (Connect-pack style, sizes 1K, 10K, 100K, 1M)

| Folder | Workload | Does |
|---|---|---|
| `start/` | `matching-preflight` | checks only (9 steps, below); run before and after setup and first when a test fails |
| `start/` | `matching-setup` | runs `matching-<size>-testauto-create` for every size |
| `tests/` | `matching-test-<size>` | what a person starts: load, then Scenarios 1, 2, 3a, 3b, 3c (RunWorkloadStep chain) |
| `schedule/<size>/` | `schedule-matching-<size>` | ScheduleTaskStep Apply: `\CrewChief\schedule-matching-<size>` runs `matching-<size>-all` (needs secret `Scheduler:RunAsPassword`) |
| `internal/<size>/` | `matching-<size>-all` + the workloads below | the same chain, for the schedule |

Every scheduled size restores the same Profisee database: set each StartTime from the measured chain duration so
they never overlap (also with Connect tests on the box).

**Connect strategy repoint** (one strategy serves every size): `scripts/retailclientimport-artifact.json` is the
gateway export (GET `v1/Connect/Strategies/<uid>`) wrapped as an `IntegrationStrategyArtifact` (`$type`,
artifactVersion 1.7.1.0, integrationStrategyRecord{Id, Name, Type, Configuration with its `$type`}), with
`{{SourceTableName}}` and `{{RunAsUser}}` tokens. Import fails "duplicated Id" when the strategy exists, so the load
deletes it first (DELETE `v1/Connect/Strategies?IntegrationStrategyUids=<uid>`); an imported strategy starts
Disabled, so a ConnExStep Enable follows. The id is kept, so it must match the empty baseline's strategy.

**Rule (Gene): a rerun always restores the scenario's start backup.** Rerun the whole workload; never rerun only the
TestAuto workflow or continue on a dirty DB, or the monitor markers and timings are useless.

## Changing anything: use the generators

The TestAuto step configs live as JSON strings inside PowerShell here-strings in
`matching-1k-testauto-create.workload.json`; do not hand-edit them. Edit and rerun the generator:

```powershell
python <skill>\scripts\gen_sizes.py C:\devops\repos\speed-merchants\CrewChief\packs\matching <skill>\scripts\connect_upsert_body.ps1
pwsh C:\devops\repos\speed-merchants\CrewChief\packs\tools\New-PackCatalog.ps1 -PackRoot C:\devops\repos\speed-merchants\CrewChief\packs\matching -Family matching
```

`catalog-meta.json` (estimate per test) is hand-kept at the pack root; `New-PackCatalog.ps1` rewrites `catalog.json` from it, `tests/` and `rounds/`; the lint fails while it is stale.

- `scripts/gen_sizes.py`: the entry point. Empties `matching/workflows`, runs `gen_all.py <size>` for every size, then
  writes each size's load workload (from `load-template-1k.workload.json` + `retailclientimport-artifact.json`),
  `-all`, `tests/`, `schedule/` and `start/matching-setup`. Sizes and default schedule times are at its top.
- `scripts/gen_s1.py <root> <upsert> <size>`: reference sets, Scenario 1 workflow, `matching-<size>-testauto-create`,
  `matching-<size>-scenario1` (health script from `health.ps1`). `gen_all.py <root> <upsert> <size>` runs it first,
  then adds 2/3a/3b/3c (workflows, run profiles, workloads, reference keys).
- `scripts/wf10000215/NN.json`: PROD workflow 10000215 step configs (read 11/05, CHUNKREF reassembled by `seq`).
  2/3a/3b/3c steps are these, patched only for: box/version tokens, size, run profile, `{{STEP:n}}`, blank
  `WorkloadExecution`, and ScenarioTable mode.
- `scripts/connect_upsert_body.ps1`: the Connect pack's workflow upsert code (after its spec), reused verbatim,
  including the 11/05 "ensure tags" block.
- `scripts/gen_preflight.py <root>`: `start/matching-preflight` (run by `gen_sizes.py` last).

Then: `pwsh packs\tools\Test-Pack.ps1 -PackRoot packs\matching -Family matching` must PASS;
`New-PackBackup.ps1 -PackRoot matching -Family matching -Destination <dir>`; `crewchief restore <zip> --folder
workloads/matching --folder reference-kv/matching --replace`; `crewchief validate workload <name> --strict`;
rerun `matching-1k-testauto-create` if a TestAuto spec changed (upsert updates in place by tag).

## Traps already hit (each cost a run)

1. **TestAuto runtime tokens inside a spec**: CrewChief resolves `{{...}}`, so `{{$config:RestClients:Profisee:ApiKey}}`
   would write CrewChief's real key into the TestAuto repository. Generators write `{%...%}`; the upsert step swaps
   back to `{{ }}`. Never put a TestAuto token in a spec with `{{`.
2. **4000-character limit**: `TestAutoWorkflowDetail.ScenarioConfiguration` over 4000 characters is stored NULL with
   a success response. Generators compact long configs and assert <= 4000; wizard-only keys (`ModelSourceDefaults`,
   `SelectedLookupAttributeCodes`, `SelectedScenarioTemplate`) are dropped in ScenarioTable configs.
3. **Saving the strategy disables it**: the continuous-matching PUT (`v1/Matching/strategies`, read-modify-write,
   autoMatch/autoSurvive true) leaves `status = 0`. Something must then PATCH `v1/Matching/RetailClient`
   `{"status":1}` and POST `processActions` `IncludeSurvivorship`: PROD's "Enable RetailClient Matching Strategy
   Then Run" step, kept in each TestAuto workflow right after the start marker (and counts). Without it Scenario 2
   ran, matched nothing, and the Activity Monitor showed no Matching rows between the markers. Doing it in CrewChief
   instead put its activity before the start marker (Gene: setup activity belongs inside the markers).
4. **Restore with SINGLE_USER deadlocks** against reconnecting Profisee services and left the DB SINGLE_USER. Use
   DatabaseOperationsStep RestoreDatabase (OFFLINE) as Connect does.
5. **Row counts**: survivorship adds golden records (match status code 10, source system 7); sparse records (too
   few match fields) never get a match status. Count loaded rows as non-golden. New rows of a BatchLoad are created
   without their source Code (Profisee assigns one), so find them as loaded rows outside the Scenario 1 table.
   Same for 3b/3c creates: their checks count non-golden records entered (`$EnterDTM`, UTC) at or after the
   scenario's start marker (`monitor.tActivity.StartedTime`, UTC). 3b run 1 (10000408) created 97 and matched 94 but
   failed a check that looked for source Codes. In 3b a few lookups hit twins created moments earlier in the same run;
   that is expected.
6. **Pool recycle time**: recycling all 20 pools takes about 2 minutes per run; the health wait follows.
7. `MatchingStrategyName` must be in the UnifiedMatchingScenario CustomParms for ScenarioTable mode (the mutator
   reads the strategy's fields); PROD's Scenario 2 config lacks it.
8. **SourceSystemDistribution must sum to TestRecordLimit**: PROD's 3a config carries Seed/Apple/Credibly
   33334/33333/33333 (100K). At 1K every lookup batch job threw `SourceSystemDistribution sum (100,000) does not equal
   TestRecordLimit (100)` and Hangfire retried 10 times with back-off (hours); the step sat Running. `lookup_patch`
   scales it to the size. Cancel a stuck execution by setting its `ExecutionStatus` to `Cancelled` (same as the UI
   Cancel); CrewChief's workflow step then fails and the run stops before its backup. From the 11/05 21:20 TestAuto
   build, `MatchingStartCheck` fails such a step once at start with this message instead.
9. **Timing target is Activities** (from 11/05 21:25): every timing step writes
   `UnifiedMatchingApiExecutionActivities` (`ActivityDetailTopN` 10). The TestAuto build and the workflow push go
   together: deploy the build, then restore the pack and rerun every `matching-<size>-testauto-create`, with no
   matching run in between; a mismatched pair writes rows to the wrong entity.

## Proof a run measured something

Activity Monitor (`monitor.tActivity`) must show Matching "Clustering & Survivorship" rows between the scenario's
Start and End markers. No Matching rows there = the strategy was disabled or continuous matching off; the run's
numbers are useless, rerun the whole workload (it restores its start backup).
A rematch that leaves a record in its cluster does not change its `Match DateTime`.
