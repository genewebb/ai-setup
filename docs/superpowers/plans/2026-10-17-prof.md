# prof Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `prof` hub (long alias `manageProfile`) that moves the AI setup and PowerShell profile to and from any machine and account, with a menu.

**Architecture:** New module `Gene.Profile` under `pwsh\PowerShell\Modules`, split by responsibility (target resolution, git sync engine, menu, verbs). The laptop clone is the hub: git works on the target clone through its admin-share path; installs run on the target over WinRM as `-User`. The machine-profile parser is the existing `lib\MachineConfig.psm1` (`Read-AIMarkdownTables`), loaded from this machine's `AIWorkRoot`.

**Tech Stack:** PowerShell 7, git, WinRM (target default endpoint is Windows PowerShell 5.1, which starts `pwsh -NoProfile -File`), `powershell-yaml` (already in `pwsh\modules.txt`). Tests use `setup\tests\TestHarness.ps1` (no Pester: machines carry Pester 3.4).

**Spec:** `docs\manageprofile-design.md`

## Global Constraints

- Command `prof`, long alias `manageProfile`. Parameter `-User` (default the caller, `DOMAIN\name`), never `-Profile`.
- No credentials stored; another account's credential is asked with `Get-Credential` on every run.
- Never overwrite an existing target machine profile without `-FixProfile` and a shown diff; never delete an old install (`-Retire` moves to `{ArchiveRoot}`).
- No GitHub on targets; the laptop is the only publisher.
- Every git call against a target clone runs as `git -c safe.directory=* -C <path>` (command-line scope is protected configuration; the scope is that one call).
- Target clones get local `core.autocrlf=false`. Worktree git runs on the target in the WinRM session; only fetch and the push to `refs/prof/incoming` cross the share (spec 4.4).
- Shared files pass `setup\Test-NoHardPaths.ps1` (`pwsh\*` is already allow-listed).

## Review Focus

1. Target tree dirtied by a live Claude session between harvest and push: the in-session `merge --ff-only` refuses only for an overlapping file, reported, nothing half-written (sync test "push refused when target dirty").
2. Both sides edited `memory\MEMORY.md`: merge succeeds, both lines kept (sync test "union merge keeps both index lines").
3. Target missing clone or machine profile: push stops with "run bootstrap" before any write (preflight test on a missing path).
4. `-User` equals the caller: no credential prompt (`Get-GeneTargetCredential` returns `$null`).
5. Menu cancelled with `q`: nothing runs (menu test).
