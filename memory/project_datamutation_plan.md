**Null cells skipped by MutationPass (2026-09-01, option 2, uncommitted; suite 972→975).** Follow-on from the coherence work: `AddressLine2` is the first kind that returns null in practice, which exposed a latent policy defect. `MutationPass.Mutate` wrote a rule's output over a NULL cell **and incremented `changed`** ("a value the source never captured is now an explicit blank"). Both halves wrong. The write turned absent into `''` — reads as PRESENT to every query downstream. The count spent one of `MaxAttributeChanges` on a column that never moved, so **a record with an absent field was silently dirtied LESS than its shape asked for**. Measured with a null column declared FIRST and a budget of 1: **0 of 213** clones got any real mutation. Fixed: `if (text is null) continue;`.

**Placement is the whole risk — the guard sits BELOW `Pick(field, ref rng)`.** Above it would skip the rule-selection draw and make the generator stream depend on whether a cell happened to be null, i.e. a function of the DATA rather than the SHAPE — unreasonable across resumes. Same hazard class as deriving `PersonIdentity` without spending a draw. Not calling `Apply` costs nothing because **no rule spends a draw on the empty string** — all 20 return on their IsBlank/length/parse guard ahead of the first `rng.Next()`; pinned by `RuleImplementationTests.Totality_EveryRule_SpendsNoDrawOnABlankValue`. **Boundary that bit me:** the invariant is the EMPTY STRING only, NOT whitespace — `Typo(" ")` hits its single-character branch and draws (doubles the char ~50%). A whitespace-only cell is a captured value and is still mutated; only null is skipped. My first version of that test probed `""`/`" "`/`"   "` and went red on Typo.

Stream still shifts for rows with a null ruled cell, not from the skipped `Apply` but from the **budget accounting**: with `changed++` gone the loop reaches later columns that then spend draws they previously did not. Only affects shapes with `AddressLine2` (or AddToExisting over legacy nulls). Same seed reproduces; not byte-comparable with the prior build.

Also fixed en route: **`WhitespaceNoise` was the only rule in the 20-rule catalog with no blank guard** — all four branches append/insert, so a blank cell came back as `" "` or `","` (red at seed 7). `Totality_EveryRule_SurvivesEveryEdgeInput` already fed `""` to every rule but asserted only non-null, which is why it hid; added `Totality_EveryRule_LeavesABlankValueBlank`. **A pre-existing test asserted the old policy** — `CloneFactoryTests.NullValue_WithBlankRule_BecomesEmptyString`, renamed to `..._StillStaysNull`. NULL is friendlier to the verifier than `''`: the 8/24 cross-unique scans needed explicit `''` exclusions, and `IS NOT NULL` already covers null. `BlankRate` deliberately still writes `''` — system character, applied after mutation, not the same concept.

**Test-writing trap worth remembering:** my budget test first passed against the OLD code because its "did anything move?" check included the null column itself, which the old policy did change (null→`''`). A red-green proof is worth nothing until the assertion excludes the very cell whose rewrite is the bug.
