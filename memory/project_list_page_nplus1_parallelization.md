The perceived "loading takes a little time" on the Scenarios / Workflows / Workflow Execution list pages is REST, not Blazor UI/SignalR. Each page loads its list in one call, then loops with a per-row awaited gateway call — a sequential 1+N fan-out. No direct SQL from the UI (all via IRestClient/facades over HTTP; SQL is behind the gateway). Delay scales with row count = the tell it's data, not the constant SignalR render envelope.

Fix pattern (matches existing `BulkCustomParmsEditorBase.cs:378` idiom): bound concurrency with `new SemaphoreSlim(10)`, project to tasks via `.Select(async … { await sem.WaitAsync(); try { … } finally { sem.Release(); } })`, then `await Task.WhenAll(tasks)`. Turns `N × RTT` into `~ceil(N/10) × RTT`. `System.Threading` is in default implicit usings — no extra `using` needed.

Applied (2026-07-12, all built EXIT=0, NOT published — user rebuilds):
- **Workflows** `Workflows.razor.cs` LoadWorkflows (~224) — parallel `GetWorkflowScenarioCountAsync` per workflow. Safe: each task writes `workflow.ScenarioCount` on its own WorkflowItem.
- **Workflow Execution** `WorkflowExecution.razor.cs` LoadWorkflows (~160) — parallel `GetExecutionDetailsAsync` per execution. Safe (own WorkflowExecutionItem). **Re-runs every 60s refresh tick** (`WebUI:WorkflowExecution:RefreshIntervalSeconds`) so payoff repeats. Detail decompression here is already lazy (only on expand).
- **Scenarios** `Scenarios.razor.cs` LoadScenarios (~175) — worst case: eager config resolve for EVERY scenario (N+1 because CHUNKREF configs each need an extra reassembly round-trip; legacy BROTLI/GZIP are CPU decompress). GOTCHA: `_scenarioConfigCache` (line 110) is a plain `Dictionary` read synchronously by render helpers (`GetScenarioConfig`/`GetStepCount`/badges) — CANNOT parallelize writes to it (data race). Pattern: tasks return `(key, config)` tuples, populate the Dictionary single-threaded AFTER Task.WhenAll; Task.WhenAll preserves order so duplicate keys stay last-wins. NOT made fully lazy because `GetTotalErrorCount` (line 462) resolves all configs anyway.
