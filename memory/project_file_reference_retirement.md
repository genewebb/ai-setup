The `ScriptKey` / `BodyFilePath` / `ScriptLocator` file-reference subsystem was retired from the MultiStepUtilityScenario framework (branch bug/max400char_scenario_data/genewebb, ~2026-06). Steps now carry **inline content only**: SqlStep.SqlScript, PowerShellStep.ScriptContent, CommandLineStep.Command, HttpRequestStep.Body. `IScriptLocator`/`ScriptLocator` are deleted; executors throw "Inline X required" if the inline field is empty (no silent-empty run). The editors no longer offer a file/script-file option. Feasible only because [[project-splitshared-v3]]'s sibling work — the chunk store ([[reference-scenariomgt-db]]) — removed the 4000-char ScenarioData ceiling, so any-size content lives inline (chunked transparently).

**Why:** file references existed only to keep ScenarioData under 4K; the chunk store made them obsolete and they were a fragile/duplicative path.

**How to apply:**
- Never suggest `ScriptKey` or `BodyFilePath` on a step — they're gone. Inline the content.
- **DEPLOY GATE (per instance, before deploying the runtime-removal build):** 1) Settings → "Convert Configs to Chunk Store" (inlines all existing scriptKey/bodyFilePath content). 2) Settings → "Audit File References" until it reports SAFE / 0 remaining (covers Scenarios + TestAutoWorkflowDetail + TestAutoWorkflowExecutionDetail). 3) The C3 fix — `ScenarioConfigStore` registered with the `RestSubjectArea.ScenarioMgt` IRestClient (NOT the default Profisee one) — must be in the build, else chunk writes hit the wrong instance and large configs silently fail to convert (symptom: large/chunked configs stay `BROTLI:` after Convert; small ones convert). ConnEx `ArtifactFile` is a SEPARATE mechanism, NOT retired.
- The "Repair Over-Compressed Configs" Config-page button + `RepairOverCompressedAsync`/`TryRepairField` were **removed** (2026-06-25) — superseded by Convert (which normalizes legacy compression). Convert + Audit are the only maintenance actions left.

**As-built clean-conversion gotchas (2026-06-25, clean prod reconvert → SAFE):**
- **8610 on `ScenarioDataDisplay`:** that preview attr is capped at 4000; convert/factory/export must TRUNCATE the resolved JSON before writing it or large/chunked configs throw 8610 and fail to convert. See [[reference-scenariodatadisplay-4000-ceiling]].
- **`{{$config:ScriptDirectories}}` token:** legacy alias resolves to the canonical `DirectoryPaths:ScriptDirectory` secret (NOT a `ScriptDirectories` key, which doesn't exist). The inliner maps script-dir aliases → `ScriptDirectoryOptions.RootDirectory`, and recovers stale absolute/reorganized `…\Scripts\…` paths under the secret root (tail-match, then unique-filename-match) so they inline + the bad path is scrubbed.
- **body + bodyFilePath:** a step with an inline `body` AND a `bodyFilePath` — the body is authoritative at runtime (DTO dropped `BodyFilePath`; `CurlExecutor` reads `Body`), so the path is dead metadata. The inliner now STRIPS the redundant path; the Audit only flags a `bodyFilePath` when the step has NO body (real dependency) + always flags `scriptKey`.
- **Convert is idempotent / skips already-converted records** (inline-JSON or CHUNKREF) — to re-apply an inliner change you must restore the legacy data and reconvert; an Audit-logic change takes effect on a plain re-Audit (no reconvert).
- Local instance gate **CLEARED 2026-06-25** (680/680, 0 errors, 0 unresolved, audit SAFE). **Prod (profiseecloud.dev/speedmerchantstest) gate CLEARED 2026-06-25** via a no-restore re-run from the local box (which has the repo `Scripts`) pointed at prod data: 83 re-processed/inlined, 597 skipped, 0 unresolved/0 errors, audit SAFE. Any OTHER instance still needs the same Convert→Audit→SAFE gate before deploying runtime removal there.
- **Convert re-processes already-converted-but-incomplete records (2026-06-25)** — the idempotency skip no longer blindly skips a converted (inline-JSON/CHUNKREF) record: it resolves the config and skips ONLY if no `bodyFilePath` remains; if one remains it re-resolves + re-inlines (or strips a redundant path). `HasRemainingBodyFilePath` gates it; `scriptKey` is excluded (can't inline → would churn). This means a re-run on a machine that now has the script files finishes records an earlier run left unresolved **without a DB restore** (critical for the Azure/SaaS prod instance, where restore = restore DB + bounce the SaaS instance). First-ever conversions are unaffected (legacy records skip the new resolve path).
- **Convert inlines file CONTENT from the filesystem of the machine running the convert** — so script files must be present there at convert time. The `bodyFilePath` `{{$config:DirectoryPaths:ScriptDirectory}}` token resolves via the per-machine secret, which is fragile (prod SMVMTR1 run gave 2 inlined / 83 unresolved because the secret pointed at the dev repo path `C:\devops\repos\…\Scripts` that doesn't exist on prod; only the 2 absolute `C:\Deploy\…` paths resolved). FIX (2026-06-25): the inliner's recovery now also searches the app's OWN bundled `Scripts` folder `AppContext.BaseDirectory\Scripts` (ships with every deployment — `C:\Deploy\TestAuto.Web\Scripts` on prod), so inlining is machine-independent regardless of the secret. Verify the fallback by pointing `DirectoryPaths:ScriptDirectory` at a bogus path and confirming it still inlines from `bin\…\Scripts`. Once everything inlines there are NO file paths left → fixed permanently. Unused prod scenarios that referenced a dev-machine path just get inlined too; no need to delete them.
