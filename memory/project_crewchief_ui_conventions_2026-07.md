CrewChief.Web UI additions/changes (2026-07-21, uncommitted) — supersedes the `crewchief-web-ui` skill where it still describes the old plain RadzenSelectBar toggle:

- **`SegmentedToggle<TValue>`** (`Components/Controls/SegmentedToggle.razor` + `SegmentedOption.cs` + scoped `SegmentedToggle.razor.css`) is now the **app-wide value-source / mode selector** — a dazzling pill with per-mode icon + accent gradient on the active segment. Params: `Options` (`IReadOnlyList<SegmentedOption<T>>` = Value/Label/Icon/AccentClass/Title), `Value`, `ValueChanged`, `Disabled`, `AriaLabel`. Accent classes: `cc-seg-literal` (blue), `cc-seg-secret` (amber), `cc-seg-ref` (green). It emits `ValueChanged`; the CALLER owns side effects (e.g. clearing the value on mode change). **Replaced the `RadzenSelectBar` in `SecretValueEditor` (Literal/Secret/Reference), `ServerNameEditor` (Secret/Reference/Text), and `EditSectionDialog` (Pick/Custom).** Any NEW mode/value-source toggle must use `SegmentedToggle`, not RadzenSelectBar. Tests find it via `cut.FindComponent<SegmentedToggle<TEnum>>()`.

- **`ExportStepsToLibraryDialog`** (`Components/Controls`, backed by `CrewChief.Data.Services.IStepLibraryExporter`/`StepLibraryExporter`) — bulk "export a workload's inline steps to the reusable step library". Auto-suggests unique kebab names (label→description→type), de-duped vs existing library + batch; new-only (never overwrites). Wired to the Workloads list (per-row `library_add` button) + the workload editor ("Export All to Library"). The editor rebuilds `_workloadFile.Steps` from `_entries.Select(ToDomainEntry)` before opening so unsaved edits are included.

- **Field-label contrast**: global `app.css` now sets `.form-label { color:#1f2733; font-weight:600 }` (titles were blending into the light cards). Every editor label is a `<label class="form-label">`.

- **Default-value affordance**: in the Configure switch table, a switch whose current value still equals its shipped default (`ConfigurationSwitchCatalog.GetSeedDefault`) renders its value cell with class `cc-default-value` (teal `#0b7285` + italic, global css) plus a `cc-default-badge` "default" chip. Helper: `StepEditorCard.IsSwitchAtSeedDefault(info)`.

- **Rename icon**: the Steps + Workloads list rows changed the rename action from `drive_file_rename_outline` (read as an edit pencil) to `title` + `ButtonStyle.Base`, so it no longer looks like the Edit button.

- **Step export/import (2026-07-21):** portable per-step bundles, mirroring the workload bundle. `IStepTransferService`/`StepTransferService` (CrewChief.Data.Services) + `StepBundle` model (`*.step-bundle.json`); BuildBundle(names)/Serialize/Parse/PreviewBundle/ImportBundle + reused `PlaintextSecretFinding`. Import is **non-destructive**: a colliding name is minted (`<name>-imported`, `-imported-2`, …) via `BuildImportName`, never overwrites. Steps page got a per-row Export (download) button + a top **Import** button + preview dialog + plaintext-secret warning (all mirroring Workloads). Registered in Program.cs + `SecretCatalogTestServices` (lazy over IStepFileStore). Tests: `StepTransferServiceTests`. NOTE: this is distinct from `ExportStepsToLibraryDialog` (which promotes a workload's inline steps into the library, not a portable file).

- **Entity cards + card/list view toggle (2026-07-21):** Steps, Workloads, and Reference Data pages now open in a **CARD view by default** with a **card/list toggle** (a Bootstrap `btn-group.cc-view-toggle` of two RadzenButton icons — `view_module`=card, `view_list`=list — active shown via `ButtonStyle.Primary` vs `Light`, mirroring TestAuto `Scenarios.razor`). View choice is **sticky per page** via existing `crewchief-io.js` `crewchiefIo.getItem/setItem` (keys `steps-view-mode` / `workloads-view-mode` / `refdata-view-mode`, value `card`/`list`), loaded in `OnAfterRenderAsync(firstRender)` in try/catch (NOT OnInitialized — prerender). Shared components **`StepCard`** + **`WorkloadCard`** (`Components/Controls`, presentational, EventCallback-driven, mirror the list-row actions) modeled on TestAuto `ScenarioCard`. **`StepCard` is color-coded by step type** via `UtilityStepTypeInfo.GetAccentColor`/`GetBgColor` (left accent bar + icon + type pill + header tint) — same idea as ScenarioCard's ColorIndex. Shared card CSS is the **`cc-card*` family in global `app.css`** (`cc-card`, `__header/__headtop/__icon/__titlewrap/__title/__typepill/__body/__desc/__tags/__tag/__toolbar`, `cc-cardbtn--run/edit/copy/rename/export/exportsteps/delete`, `cc-card-grid` responsive auto-fill grid, accent via `--cc-accent`). List views keep the original RadzenDataGrid unchanged.

- **Reference Data rework (2026-07-21):** types shown as `cc-card`s (card default) or a compact paged list (25/page: `_typePage`/`TypePageCount`/`PagedTypes`/Prev-Next footer). The per-type **"Usable in replacements" (`IncludeInReplacements`) switch is on the card face AND each list row**, toggled inline without selecting the type via new `SetReplaceableFor(string type, bool)` → `Store.SetIncludeInReplacements` (old `SetReplaceable(bool)` delegates to it). Per-type counts/flags cached in `_entryCounts`/`_replaceableByType` (rebuilt in `RebuildTypeCaches`). Entry editing is now a **single-entry (key+value) popup** (`_showingEntryDialog`, `OpenNewEntry`/`OpenEditEntry`/`SaveEntryDialog`, key editable only when new, plain-text value) — removed the old inline `_newKey`/`AddEntry`/`SaveEntry`.

- **Configure editor = wizard, FULLY REDESIGNED v3** (details in [[project_crewchief_configure_switches]]): 9 purpose-built pages (Settings/Target/License/SQL/Web & IIS/Authentication/Integrations/Advanced/Review) in a matching-wizard shell (named indicator + Previous/"Step X of N"/Next + one `cc-cfg-panel` with title—description header). Anti-scroll core: **enabled switches = 2-up form fields; disabled = "+ add" chips** that promote on click. Review page = stat tiles + masked switch summary + PowerShell preview. `SubGroup` on `ConfigurationSwitchInfo` now feeds page SECTIONS (not tabs). Host edit-step modal widened to `max-width: min(1000px, 96vw)`.

- **WorkloadEditor step-header pills (2026-07-21, done):** each step row in `WorkloadEditor.razor` got a left **accent bar + `cc-seq` sequence circle colored by step type** (`GetAccentColor`/`GetBgColor`), a truncated title, and compact **`cc-steppill`** chips (type pill + Ref/Unreadable + a "Details" pill shown when a Label hides the description) — each with the detail in a `title=` hover tooltip (`cursor:help`), mirroring TestAuto `ScenarioCard`'s pill idiom. Pill CSS (`cc-steppill`/`--muted`/`--danger`, `cc-seq`, `cc-steptitle`) in global `app.css`. The reorder/expand/save/duplicate/delete toolbar + collapsible per-step body (inline `StepEditorCard`) left intact.

- **UI round 3 (2026-07-21, user-approved formats):** (1) **Card-mode paging everywhere** — Steps/Workloads card grids page with the grid's ListPageSize (PagedCardSteps/PagedCardWorkloads + Prev/"Page X of N"/Next pager, reset on filter change); refdata card grid reuses its shared `_typePage` pager. (2) **Micro-row cards** — StepCard/WorkloadCard are ~2 lines: hover-revealed select checkbox, accent icon, truncated name w/ "{TypeName} — desc" tooltip, ghost Run/Edit + `more_vert` kebab menu (Copy/Rename/Export/Delete; menu ALWAYS in DOM, CSS-hidden, so bUnit `button[title=...]` selectors keep working); parameter surfaces unchanged; new `cc-card--micro`/`cc-mcard*` classes in app.css, legacy cc-card classes intact for refdata. (3) **Step-editor "command bar + collapsibles"** — dialog header = type icon+display name once + Change Type + Name w/ (i) kebab-tooltip + Save; "▸ Tags (N)" and "▸ Execution — {t}s · retry · cwd" collapsed rows (bodies kept in DOM via d-none for bUnit); disabled Type input removed; kebab helper text everywhere → (i) tooltips (Steps/Workloads/refdata/WorkloadEditor dialogs). (4) **Activity full execution treatment** — stat tiles (Total/Complete/Running/Cancelled/Failed via CountFor), 5px striped progress from `RunProgressPercent` (StepResults.Count vs TotalSteps), scoped `.status-pill` classes replace badges (running pulses), "● live" badge; NO new polling (event-driven). (5) **WorkloadEditor TestAuto-style** — `wl-seq` 1.625rem accent circle numbers, clickable header band collapse w/ max-height animation (4000px ceiling; StepEditorCard body lazy-rendered on first expand via BodyRendered latch, stays in DOM after), sc-toolbar-style colored square action buttons, Expand/Collapse All; ONE top action row (Export All + Add from Library + Add Inline + divider + Cancel/Run/Save); Tags + Global Parameters collapsed rows (`wl-collapse-row`). Scoped css files: Workloads/KeyValueReferenceData/Activity/WorkloadEditor `.razor.css`.

- **WorkloadEditor card/list toggle (2026-07-22):** the step list has the same view toggle as the other pages (`cc-view-toggle` btn-group, sticky key `workload-editor-view-mode`, **card grid default**): card mode = compact `cc-card` grid (wl-seq number circle, type icon/pill, Ref/Unreadable pills, toolbar Edit/Export/Duplicate/Delete; checkbox keeps bulk-move working); Edit on a card calls `EditEntryFromCard` → switches to the detail list with that entry expanded (deliberately does NOT persist the view pref). Detail list = the full TestAuto-style editor (reorder, inline StepEditorCard); Expand/Collapse All only shows in detail view. bUnit note: `WorkloadEditorPageTests` that assert detail-view elements must call `SwitchToDetailView(cut)` (clicks `button[title='Detail list view']`) after render.

- **Card-pager v2 + Activity summary card (2026-07-22):** card-mode pagers are now **always visible** whenever the filtered list is non-empty (previous >1-page-only rendering read as "no paging"): footer bar = "Showing F–L of T" + Per-page RadzenDropDown + Prev/"Page X of N"/Next. Steps/Workloads: mutable `_cardPageSize` seeded from ListPageSize (config), independent after user change. WorkloadEditor card grid: paged too (`_stepCardPage`/`_stepCardPageSize` default 12, options 6/12/24/48 page-local; ABSOLUTE step indexes kept on number circles; add/duplicate jumps to the new step's page; detail list stays unpaged). Activity: stat tiles wrapped in bordered `#activity-summary-card` with a 10px overall progress bar + "Step X of Y — elapsed" while a run is active (existing 1s ticker, no new timers); run rows get 4px status-coloured left accents (`RowAccentClass`); pager switched to the same always-visible footer — NOTE: the old First(«)/Last(») jump buttons were dropped in the process.

- **Activity detail = TestAuto execution panel (2026-07-22, user-approved items 1–8):** expanded run row now renders an **exec-header card** (EXECUTION panel: name+outcome pill+kind chip+started/ended/duration; PROGRESS panel; ACTIONS panel hosting Cancel / restart-select / Restart / Resume — ids unchanged), a **FailureBanner** (first failed step + how many steps never started; cancellation note), a **labeled percent progress bar for every run** (`DetailBarClass`: animated live, bg-success/danger/secondary terminal), and a **numbered step list** (`.exec-steps`, 1-based "N. Name", status pill + type·duration, per-step `description` button → `#activity-step-dialog` modal with Output/Error — the old inline output dump is GONE). Page header: subtitle + idle `live-badge--idle` "updates in real time" (event-driven, no polling); **name filter** input (`_nameFilter`, resets page) beside status pills; Kind renders as `kind-chip--workload` (teal) / `--step` (indigo); **whole row click expands** (`activity-row--clickable`; checkbox/expand/delete stopPropagation — expand button MUST keep stopPropagation or the bUnit double-click toggle test breaks). StepResultRecord has NO per-step start/end timestamps — step meta shows status+type+DurationMs only.

- **Card grid 3-up + per-page cards-per-row picker (2026-07-22):** shared `.cc-card-grid` (app.css) changed from `auto-fill minmax(280px,1fr)` (5-6 skinny columns) to a fixed **3-up desktop default**, with `.cc-card-grid--2`/`--4` modifier classes and media queries (declared AFTER the modifiers so they win) clamping every choice to 2-up <1200px / 1-up <768px. Steps, Workloads, and WorkloadEditor card views each host a **SegmentedToggle<int> 2/3/4 picker** next to the card/list toggle (visible only in card view), sticky per page via crewchiefIo keys `steps-card-cols` / `workloads-card-cols` / `workload-editor-card-cols` (restored in OnAfterRenderAsync, clamped 2–4). Pattern per page: `_cardCols` + `CardColsClass` + static `CardColumnOptions` + `SetCardColsAsync`; grid div = `class="cc-card-grid @CardColsClass"`. KeyValueReferenceData keeps the plain 3-up default (no picker).
