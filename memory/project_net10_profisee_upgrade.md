On 2026-07-13 speed-merchants was upgraded from net8.0 → **net10.0** and all referenced `Profisee.Platform.*` packages bumped to latest, on branch `bug/documentation_updates/genewebb`. Full solution builds clean (0 errors). Central Package Management → all versions live in `Directory.Packages.props`.

**Framework bump:** all 24 csproj `net8.0`→`net10.0`; the ~25 framework-tied packages (`Microsoft.Extensions.*`, `Microsoft.AspNetCore.*`, `Microsoft.EntityFrameworkCore.*`) → `10.0.9` (match installed runtime). Also flipped the 2 `.pubxml`, `speed-merchants.runsettings`, and `Diagnose-DeployedMachine.ps1`.

**net10 build breaks fixed:**
- **CS0433 ambiguous `Program`** in Integration tests (both `TestAuto` and `TestAuto.Web` expose a global top-level `Program`). Fixed with `extern alias`: `Aliases="global,TestAutoWeb"` on the TestAuto.Web ProjectReference + `extern alias TestAutoWeb;` and `WebApplicationFactory<TestAutoWeb::Program>` in ControllerTestBase.cs / IntegrationTestBase.cs. The `global,` prefix is mandatory — 20 other Integration files use `TestAuto.Web` via the global alias.
- **CS2001 missing MD2Razor `.g.cs`** — stale obj cache after framework switch; fixed by deleting all bin/obj and clean rebuild.

**The NServiceBus 7 ceiling (KEY, will recur next upgrade):** `Profisee.Platform.Utilities.Messaging` latest `3.0.0.18` is built on **NServiceBus 8** (and renamed the transport `NServiceBus.SqlServer`→`NServiceBus.Transport.SqlServer`). But `Profisee.Platform.Utilities.Monitor.Messaging` latest `1.0.0.679` is **still NServiceBus 7** (depends on NSB 7.8.1 + Messaging 2.0.0.127 + NServiceBus.Serilog 6.3.2). One process = one NServiceBus.dll, so they can't coexist. Decision: **held NServiceBus at 7** → kept `Messaging` at `2.0.0.127` (its latest 2.x), bumped everything else Profisee to latest. Revisit Messaging 3.x only once Profisee ships an NSB-8 Monitor.Messaging. Repo NServiceBus usage is thin (7 files, mostly `IMessageSession` + Profisee wrapper `MessagingPublishSubscribeEndpointBase`); no raw endpoint-config code.

**Forced transitive floor bumps (from latest Profisee pkgs, not framework):** `Microsoft.Data.SqlClient` 6.1.0→7.0.2, `Newtonsoft.Json` 13.0.3→13.0.4 (from Monitor.Messaging 1.0.0.679); `Serilog.Extensions.Logging` 8.0.0→10.0.0, `Serilog.Settings.Configuration` 8.0.4→10.0.1, `Serilog.Sinks.Console` 6.0.0→6.1.1, `Serilog.Sinks.Seq` 8.0.0→9.1.0 (from Utilities.Logging 1.0.1.173). Read the bumped pkgs' `.nuspec` in `~/.nuget/packages/<id>/<ver>/` to get all floors in one pass instead of build-by-build.

**Code API breaks fixed:** Profisee CDP `IContext` (Utilities.Cdp 1.1.0.883) added `string ServiceName { get; }` — implemented `=> MonitorActivityConstants.ServiceName` ("TestAuto") in Context.cs, CdpContext.cs (Shared) + Integration Context.cs. `TestAuto.Scenarios` had a production `using FluentAssertions` (`.Should()` in ScenarioQueueLoadManager.cs:141) that used to come transitively; added an explicit `FluentAssertions` PackageReference (pinned 6.7.0).

**Cross-repo package consistency (checked 2026-07-13):** Only 2 prerelease pins, both fine — `NServiceBus.Extensions.Diagnostics.OpenTelemetry 2.1.0-rc.1` matches governance & rest-api (platform standard); `System.CommandLine.NamingConventionBinder 2.0.0-beta4` has no stable 2.0 release. speed-merchants is now AHEAD of the platform repos (they're net6/net8 + older Profisee): `Microsoft.Data.SqlClient 7.0.2` (platform on 5.2.x — forced by latest Monitor.Messaging) — user chose to KEEP 7.0.2 (stable, separate process from platform services). Newer Serilog sinks forced by latest Utilities.Logging. All divergences are stable and are the cost of net10 + latest-Profisee.

**Vulnerability remediation (2026-07-13, user asked "fix both properly"):** cleared all NU1902/NU1903 transitive-package advisories (warnings 146→0). Also removed 4 redundant NU1510 framework-provided PackageReferences afterward for a fully clean build: Microsoft.AspNetCore.Components.Web (TestAuto.Web, Web SDK provides it) and Microsoft.Extensions.Options/Logging.Abstractions/Configuration.Abstractions (TestAuto.Shared.Http, which has FrameworkReference Microsoft.AspNetCore.App) → **final build is 0 warnings / 0 errors**. (1) `System.IO.Packaging` 8.0.0 (HIGH ×2: GHSA-f32c-w444-8ppv, GHSA-qj66-m88j-hmgj) came via `Microsoft.PowerShell.SDK 7.4.3`→`Microsoft.Windows.Compatibility`; pinned to **10.0.9** by adding a direct `<PackageReference Include="System.IO.Packaging" />` in TestAuto.Shared.csproj (flows repo-wide since everything refs Shared) + a `Version="10.0.9"` in Directory.Packages.props. (2) `OpenTelemetry.Api 1.2.0-rc1` (moderate) came via `NServiceBus.Extensions.Diagnostics.OpenTelemetry 2.1.0-rc.1`→`OpenTelemetry 1.2.0-rc1`, which was **referenced but used nowhere in code** — removed the PackageReference (TestAuto.Shared.csproj) + its PackageVersion entirely, killing the whole rc chain (platform/governance instead keep it and NoWarn NU1902). Earlier the Profisee bumps already cleared the Azure.Identity / Microsoft.Identity.Client / System.Security.Cryptography.Xml advisories (Crypto.Xml pulled to 10.0.9).
