Fixes/gotchas for the `crewchief` CLI (CrewChief.Cli, AssemblyName `crewchief`), from live testing 2026-07-23 (all uncommitted; user rebuilds/republishes):

- **InvariantGlobalization MUST be false.** `CrewChief.Cli.csproj` had `<InvariantGlobalization>true</InvariantGlobalization>` → `Microsoft.Data.SqlClient` throws `System.NotSupportedException: Globalization Invariant Mode is not supported` on `SqlConnection.Open()`, so DatabaseOperations/SetApiKey/SqlStep die from the CLI (Web app was never invariant). Set to false (commented). Symptom flavor: fails at `SqlConnection.TryOpen`; distinct from "Connection string not found for secret 'X'" which is a *config* miss at `ResolveConnectionString` (before any open) — the demo `all-step-types` workload hits the latter by design (no `DemoDb`).
- **Run-table display** (`RunCommand.PrintStepLine`/`PrintStepTableHeader`): IDX is now 1-based (was 0-based `StepResultRecord.Index`) to match the Web UI; added a `Fit(value,width)` helper (truncate-with-ellipsis + guaranteed gap) so long names/types can't overrun columns (`,-28`/`,-20` padding only sets a MINIMUM). Widths IDX5/NAME30/TYPE24/STATUS20.
- **"crewchief not on PATH after a checked install" is NOT an installer bug.** `installer\CrewChief.iss` `AddCliToPath()` correctly writes `{app}\cli` (= `C:\Program Files\CrewChief\cli`) to the machine PATH (HKLM Session Manager\Environment), gated `if WizardIsTaskSelected('clipath')` in `ssPostInstall`; verified present via `[Environment]::GetEnvironmentVariable('Path','Machine')`. The symptom = the **terminal cached its env at launch** (waveterm / Windows Terminal / VS Code snapshot env per app-launch, not per tab) → session PATH stale → bare `crewchief` fails AND `.\` needed even in the folder (PowerShell never runs CWD exe implicitly). Fix: fully restart the terminal app (or sign out/in), or `$env:Path += ';C:\Program Files\CrewChief\cli'` for the current session.
- **Default install path → `C:\Deploy\CrewChief`** (2026-07-23): `.iss` `DefaultDirName={sd}\Deploy\{#AppName}` (was `{autopf}\{#AppName}`). The dir-select page was ALREADY shown (no `DisableDirPage`) and all paths are `{app}`-relative, so a custom folder always worked — only the default changed. Updated every doc + installer `GETTING-STARTED.md` that hardcoded `C:\Program Files\CrewChief`. Note: outside Program Files loses that ACL protection for a LocalSystem service's binaries (secrets still live in %ProgramData%). **Same change applied to the TestAuto installer** (`installer\TestAuto.iss` at the repo root, built by `New-TestAutoInstaller.ps1`): `DefaultDirName={sd}\Deploy\{#AppName}` → `C:\Deploy\TestAuto`, its `installer\GETTING-STARTED.md` paths updated. TestAuto has NO PATH/clipath task (shortcuts-only, no service, no CLI-on-PATH) so nothing to flip there; dir page already selectable. Packaging transient failure `EndUpdateResource failed (110)` at the ISCC step = real-time AV locking the freshly-written Setup.exe — retry ISCC (exclude installer\output from AV to stop it recurring); NOT a code/.iss issue.
- **`clipath` task now ships checked-by-default** (removed `Flags: unchecked` 2026-07-23, per user) so the CLI lands on PATH without remembering to tick it. Still user-overridable at install.
- **CLI run console = pass/fail only** (2026-07-23): Serilog console sink dropped to `Fatal` by default (was `Warning`) so engine ERR/WRN + stack traces no longer clutter the per-step table; full detail stays in the rolling `logs\crewchief-cli-<date>.log`, whose path is printed at the end of run/resume (`PrintLogLocation` finds the newest file). `--verbose` restores full console logging.
- Help docs split: `30_OpsWebUiAndCli.md` → `30_OpsWebUi.md` (/help/operations/web-ui) + `30_OpsCli.md` (/help/operations/cli); the CLI doc documents with/without-PATH invocation, the `.\` rule, and the terminal-restart caveat. Unit suite 1517 green.
