`ConfigureStep` no longer has ~13 ad-hoc typed fields (Mode/SqlServer/WebSiteName/…). It's a `[JsonProperty("switches")] Dictionary<string,string> Switches` (enabled switch name → value; bools stored `"TRUE"/"FALSE"`). `ComposeArgumentString()` emits `/name:value` per entry ordered by name — value double-quoted only when it contains whitespace — then appends the raw `Arguments` escape hatch. `ConfigurationExePath`/`Arguments`/`TargetComputer`/`CredentialSecretName` retained.

Metadata for all **61** Configuration.exe switches lives in `CrewChief.Web\Helpers\ConfigurationSwitchCatalog.cs` (name, type Bool/String/Path/Enum, group, description, secret, mode, default + `DefaultEnabled`/`PreferredDefault`), transcribed from the platform source `C:\devops\repos\platform\Server\Configuration\Program.cs` (parser `Common\Common\CommandLineParser.cs`: `/name:value` or `/name=value`, bools `/name:TRUE`, quotes stripped, `@file` response files, duplicate-key aborts). **Coverage verified 2026-07-21**: catalog fully covers the canonical ground-truth invocation `C:\devopslocal\MyScripts\ConfigureProfisee.ps1` (all 38 switches present) — the SMVM3 "Missing parameter X" one-at-a-time discovery loop is CLOSED; last three added were `maestroServicePort`/`maestroServiceUserName`/`maestroServiceUserPassword` (IIS group). Note: the correct Purview tenant switch is `purviewTenantId` (single-n, confirmed at `Program.cs:1511`); the user's script has a harmless `purviewTennantId` typo (empty + Purview disabled).

Two-tier reference data (renamed from single `configuration-defaults`): `configuration-template` = the map new Configure steps prefill from (mostly `{{$config:...}}`/`{{$ref:...}}` tokens; since 2026-07-22 also a few benign literals — `FALSE`/`Windows`/`Interactive`/empty strings); `configuration-values` = the actual replaceable values. Shipped as `DefaultReferenceData/*.refkv.json` embedded resources, installed via `ReferenceDefaultsSeeder` (additive 3-way merge, preserves operator edits; new shipped KEYS land on existing installs via the key-diff vs the manifest's previously-shipped list).

**Default-enabled profile widened 2026-07-22** (user: a new Configure step should pass most switches like the canonical script, empty where unused): `DefaultEnabled` added to `dropMaestroDatabase`(FALSE), `sqlUserName`(""), `sqlUserPassword`(""), `UseSeparateDatabases`(FALSE), `authAdName`(Windows), `AttachmentRepositoryLogonType`(Interactive, via PreferredDefault), `purviewURL`/`purviewTenantId`/`purviewClientId`/`purviewClientSecret`(""). Template refkv gained matching literal entries (+ `_shippedUtc` bump). OIDC switches stay off by default (env-specific). `ComposeArgumentString` emits an enabled-blank switch as `/name:` — equivalent to the script's `-name:""`. Remember: `DefaultEnabled` alone yields a BLANK value on new steps (values come only from the template set) — always add the template entry too.

**Editor (FULL REDESIGN 2026-07-21, v3)** — Configure branch of `StepEditorCard` is a hand-rolled WIZARD mirroring TestAuto `UnifiedMatchingScenarioEditor` (NOT RadzenSteps/RadzenTabs): clickable named step indicator (`cc-wizard-steps`, no numbers) + `cc-wizard-nav-bar` (Previous / "Step X of N" / Next) + ONE `cc-cfg-panel` at a time with a title—description header. **9 purpose-built pages** (`ConfigureEditorTabs`, record `ConfigEditorTab(Key,Label,Description,Count)`): Settings, Target & Run As, License, **SQL / Database, Web & IIS, Authentication, Integrations** (switch pages from `ConfigSwitchPageLayout` → `ConfigureSwitchPages`, each = titled `ConfigSection`s mapped from catalog (Group,SubGroup) parts), Advanced (One-Shot Modes section via `ConfigureModeSwitches` [Group=="Mode"] + raw args), Review. **Anti-scroll core: enabled switches render as real 2-up form fields (`cc-cfg-field`, DisplayName label w/ title-tooltip = description+/name, X-to-remove); disabled switches collapse into dashed "+ add" chips (`cc-cfg-addchip`, hover=description) that promote to fields on click** — a page shows 3-6 fields typically, not 16 cells.
