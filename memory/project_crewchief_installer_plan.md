UPDATE 2026-07-23 (optional service account): installer no longer hardcodes LocalSystem. New wizard page (CreateCustomPage after wpSelectDir, shown only when the `service` task is selected) offers **LocalSystem (default)** vs **a specific Windows account** (user+password). Why: local-mode box-prep steps IGNORE the step Run-As credential, so a Configure step whose SQL is on ANOTHER box hit `Login failed for 'DOMAIN\<machine>$'` (LocalSystem → machine account, no SQL login) — see [[crewchief-remote-box-prep]] local-vs-remote. New `installer\Grant-ServiceLogonRight.ps1` (LSA `LsaAddAccountRights`, additive/idempotent) grants SeServiceLogonRight — sc.exe does NOT (else error 1069); staged via `[Files] Flags: dontcopy` + ExtractTemporaryFile. TPasswordEdit (NOT TNewEdit.Password — no such property). No silent-install params (no automated deploys). Design doc: `99 Documentation\speed-merchants\planning\Design_CrewChiefInstallerServiceAccount.md`.

UPDATE 2026-07-24 (identity is fresh-install-only, user directive): the 07-23 "preserve unless changed" wizard-state logic RESET a manually-reconfigured service back to LocalSystem when the page state was never initialized (silent reinstall / page never shown → RbLocalSystem default → `obj= LocalSystem` applied). Replaced with the hard rule: **`InstallOrUpdateService` emits `obj=`/`password=` (and grants SeServiceLogonRight) ONLY when the service does not exist**; on upgrade `sc config` carries binPath/start only, and `ShouldSkipPage` skips the account page when `ServiceExists()`. Post-install identity changes are made in services.msc and the installer never touches them again. OriginalIsLocalSystem/OriginalUser/ServiceAcctDefaulted/CurPageChanged machinery deleted. Compiles clean (ISCC 7, dummy-stage /Qp check).
