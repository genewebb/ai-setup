CrewChief's separate **Execution** (`/execution`, `/workloads/execution`) and **History** (`/history`) Blazor pages were merged into ONE page: **Activity** (`Activity.razor`/`.cs`, route `/activity`), nav icon `monitoring`. Single nav entry "Activity" (NavMenu.razor); MainLayout run-indicator now links `/activity`.

Key design:
- Old routes `/execution`, `/workloads/execution`, `/history` are kept as extra `@page` directives on Activity.razor so old links/bookmarks still resolve (back-compat).
- Lists ALL run kinds (step + workload) newest-first; sticky status-filter buttons (All/Running/Succeeded/Failed/Cancelled) — see [[reference_crewchief_sticky_filters]].
- **Hand-rolled `<table>`, NOT RadzenDataGrid** — rows expand accordion-style keyed by `run.Id` (single `_expandedRunId`) so the 1s live-elapsed ticker's re-renders never collapse the open row (RadzenDataGrid keys expansion by item instance, which resets when `GetAll()` returns fresh instances each refresh).
- All actions on one page: Cancel / Restart-from-any-step / Resume via IWorkloadRunCoordinator (in-place, no nav), per-row Delete, bulk Delete Selected + select-all, Delete All, Refresh. Resume no longer navigates to Workloads `?resumeRunId=` (that Workloads handler still exists, now unused by UI).
- Detail element ids for tests: `activity-step-table`, `activity-restart-select`, `activity-restart-btn`, `activity-resume-btn`, `activity-running-badge`, `activity-cancel-btn`, filter buttons `activity-filter-{status}`, expand `activity-expand-{guid}`.

GOTCHA: the page class `Activity` collides with `System.Diagnostics.Activity` used in `Error.razor` (same `CrewChief.Web.Components.Pages` namespace) → Error.razor must fully-qualify `System.Diagnostics.Activity.Current`.

Shared run-display statics (OutcomeBadgeStyle/OutcomeIcon/FormatDuration/SucceededStepCount/FormatElapsed/TruncateForDisplay/CanResume) were lifted off the deleted History page into `RunDisplay.cs` (static, namespace `...Components.Pages`); Workloads.razor + WorkloadEditor.razor reference `RunDisplay.X` now. Tests: `ActivityPageTests` (replaced ExecutionPageTests + HistoryPageTests), `TestableActivity` overrides `ConfirmAsync`.
